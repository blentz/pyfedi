## Harness facts, established by execution during scoping

- **The copy POST must be multipart.** `feed_copy:268` and `:273` read
  `request.files['icon_file']` / `['banner_file']` directly, so a urlencoded
  POST is a bare **400** before any form logic runs. Send both parts as empty
  files: `{'icon_file': (io.BytesIO(b''), '')}`.
- `render_template` must be patched for every GET (fact 292), and the POST
  arms that fall through to a re-render.
- `search_for_feed` is imported into `app.feed.routes` from
  `app.feed.util` — patch it there.
- The copy form is the same `AddCopyFeedForm` as `feed_new`, so `communities`
  is required (fact 294); `form_communities_to_ids` is NOT called by this
  route, which builds its `FeedItem` rows from the source feed instead, so no
  patch is needed for it.

## Task 1: P1-P4 — the four repairs, pinned together and fixed together

They are one commit's worth of work in one function, and three of them are
defects this campaign has already repaired elsewhere, so the pins say that
explicitly and name the entry each one repeats.

**Pins** (all pass against the current tree):

1. a non-admin copying a feed produces `is_instance_feed True` — D675's shape;
2. the same POST on a site with both switches off produces `nsfw True, nsfl
   True` — D702's shape;
3. the GET pre-fill leaves `nsfl.data` False for a source feed with
   `nsfl=True` — D701's shape, verbatim;
4. the copied row's `ap_outbox_url` is `None`.

**Fixes:** the admin check and the site coercion as `make_feed` and `feed_new`
carry them, `copy_feed_form.nsfl.data = feed_to_copy.nsfl`, and the outbox url
built the way `make_feed:226` builds it.

**Inversions**, each with the control that makes it a kill: an admin still gets
an instance feed; a site with one switch on honours exactly that one; the
pre-fill's disabled arm still leaves the field alone; the outbox url is asserted
as the exact string, not merely non-None.
